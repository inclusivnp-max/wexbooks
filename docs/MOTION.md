# WexBooks — анимации как часть качества

## Принцип

Движение объясняет изменение состояния и подтверждает касание. Оно не задерживает действие, не отвлекает от текста и не продолжает жить само по себе на неподвижной странице.

Общие переходы находятся в `ui/motion/WexMotion.kt`; типографический morph — в `TextMorph.kt`, `NativeTextMorph.kt`, `WexAnimatedText.kt`, адаптер EPUB — в `EpubTextMorph.kt` и `assets/motion/text-morph.js`.

## Текущая система

| Сценарий | Поведение |
|---|---|
| Нажатие на стеклянную кнопку | Масштаб до 0.94 и возврат через spring: dampingRatio 0.82, stiffness 500 |
| Переключение вкладки | Индикатор скользит к новому пункту с той же пружиной; оттенок текста меняется за 160 мс |
| Смена содержимого вкладки | Вход: fade 200 мс и короткий направленный сдвиг 260 мс; выход: fade 110 мс и меньший сдвиг 220 мс |
| Библиотека → демо-книга | Согласованные переходы текста и панелей; направление меняется при возврате |
| Повторное касание во время перехода | Новая выбранная вкладка становится целью текущего движения; очередь длинных анимаций не создаётся |
| «Меньше движения» | Snap вместо пружин и переходов, без сжатия кнопок; состояние сохраняется при пересоздании Activity |
| Бездействие | Нет бесконечных анимаций, декоративного shimmer и пульсирующей оптики |

Compose также учитывает системную длительность анимаций. Собственная настройка делает спокойный режим явным внутри приложения.

## Следующие этапы

1. **Реальная книга:** согласовать переход обложки/карточки и появление страницы после выбора книжного renderer. Не создавать белый кадр при загрузке.
2. **Панель Aa и оглавление:** движение вслед за пальцем, сохранение скорости при отпускании, прерываемая пружина; модальная панель не выталкивает текст случайно.
3. **Перелистывание:** первым сделать чистый сдвиг или мгновенную смену страницы; имитацию бумаги предлагать отдельно и только после замеров. Не связывать доступность функции с дорогим эффектом.
4. **Изменение шрифта:** обновлять настройки управляемо, сохранять смысловой якорь и показывать понятный результат. Не перепагинировать всю книгу каждый кадр ради «плавного размера букв».
5. **Выделение:** меню появляется возле выделения без прыжка страницы; drag-маркеры и системные жесты остаются предсказуемыми.
6. **Импорт:** прогресс отражает реальную работу; неизвестную длительность не изображаем выдуманным процентом.
7. **Ошибка:** короткое понятное изменение состояния, повтор действия без полной перезагрузки экрана.

## Что проверяем отдельно

- Переход работает вперёд и назад, в том числе если пользователь передумал на середине.
- Быстрые касания вкладок заканчиваются на последнем выборе; выходящие экраны исчезают из доступности.
- Изменение темы обновляет и содержимое, и системные статусные значки.
- Положение книги не зависит от длительности анимации.
- Системный масштаб анимаций 0 и «Меньше движения» не ломают действия.
- Шрифт 200%, TalkBack, клавиатура и ориентация не прячут основные действия.
- 60/90/120 Гц проверяются на реальных аппаратах в release-like сборке через Macrobenchmark/Perfetto.
- Нагрузка стекла измеряется отдельно от книжного движка; в неподвижном чтении не должно быть постоянных redraw.

## Уже автоматизировано

UI-тест с ручными часами Compose проверяет, что индикатор действительно перемещается, затем прерывает движение новой вкладкой и проверяет конечную выбранную вкладку. Другой UI-тест проверяет настройки уменьшения движения/прозрачности после пересоздания Activity.

UI-тесты и замеры запускаются на физическом Pixel через USB. Эмулятор не используется.

## Подмена текста в духе Telegram Android

Референс — поведение [AnimatedTextView в Telegram Android](https://github.com/DrKLO/Telegram/blob/master/TMessagesProj/src/main/java/org/telegram/ui/Components/AnimatedTextView.java), а не печатная машинка или каскадное проявление строк. Реализация WexBooks самостоятельная: ограниченный LCS сопоставляет одинаковые графемы; общие символы сохраняют видимость и переезжают, новые въезжают с небольшой вертикальной амплитудой, исчезающие уходят с затуханием. Длительность 280 мс, easing cubic-bezier(.23,1,.32,1), амплитуда около 0.3 высоты строки. Сопоставление в книге ограничено строкой, чтобы буквы не летали через всю страницу.

### Нативный текст
- Один Canvas и две временные alpha-текстуры размером не больше viewport; после завершения остаётся только текущая.
- Текст шейпится обычным TextMeasurer. Атлас рисуется один раз при смене страницы; на каждом кадре двигаются уже готовые фрагменты, без нового измерения текста.
- Графемы разделяет Android ICU. Шейпинг, лигатуры и курсив берутся из исходного растра, а не рисуются повторно как изолированные буквы.
- Одинаковые соседние траектории объединяются в runs. На обычной странице до 1200 графем; особо плотный хвост переходит целыми строками. Viewport больше 3 млн пикселей использует мгновенное обновление.
- Проценты и значения Aa используют тот же механизм, семантика доступности содержит только актуальный текст.

### EPUB
- Адаптер работает через публичные WebView/DOM API, без reflection и форка Readium.
- Координаты видимых графем считываются один раз при смене страницы, до 900 графем / 2500 просмотренных текстовых узлов / 1800 проверок координат. Текстовые узлы длиннее 16 384 символов остаются обычным текстом, чтобы не сканировать огромный абзац ради декоративного эффекта.
- Временный aria-hidden Canvas-overlay рисует анимируемые runs из двух растров viewport. Это один рисуемый слой, а не сотни DOM span/WAAPI-слоёв; растры создаются один раз при смене страницы, не каждый кадр. Исходный текст не разбивается span-элементами и не переписывается: вёрстка, выделение и TextQuote-якоря остаются исходными.
- [CSS Custom Highlight API](https://developer.mozilla.org/en-US/docs/Web/API/CSS_Custom_Highlight_API) временно скрывает ровно соответствующие диапазоны. Overlay и highlights удаляются после завершения, отмены и закрытия книги.
- Без CSS Highlight API буквенный overlay выключен; остаётся штатный переход Readium. Физический растр ограничен 3 млн пикселей на viewport. При вертикальном чтении и уменьшении движения буквенный эффект выключен.

### Диалоги
Собственный `WexDialog`: общий стеклянный материал, собственные кнопки и BasicTextField, вход/выход scale+translation+alpha, состояние сохранения и блокировка повторного действия. Уменьшение прозрачности и движения наследуется от настроек приложения. Material AlertDialog в интерфейсе больше не используется. Материальные нижние панели остаются отдельной задачей по хореографии.

### Проверки
`TextMorphTest` проверяет идентичность, вставки/удаления, порядок повторяющихся букв, графемы и лимиты. `TextMotionTest` на Pixel сравнивает промежуточный и финальный растр нативной страницы; проверяет реальный запуск EPUB morph, неизменность body.textContent, удаление overlay и работу уменьшенного движения. Показатели кадровой нагрузки — в PERFORMANCE.md, без обещания 120 FPS во всех книгах.
