# Производительность на Pixel 9 Pro XL

Дата: 25 октября 2026. Android 17 / API 37. USB ADB, без эмулятора.

## Методика

Macrobenchmark 1.5.0 запускает отдельное приложение `.benchmark`: non-debuggable, profileable, тот же release-like код, CompilationMode.None. Холодный старт — 5 повторов; перелистывание — 3 повтора по 12 переходов. Настройки частоты экрана/анимаций телефона не менялись.

База — EPUB-реализация до перехода на общее ReaderCore. Контрольный APK: SHA-256 `304230e64fdb3e76bd67ac9ff04a0f2b9d8577395345587609c8faa4ef120fff`. Итог — ReaderCore, исправленные цвета и облегчённый материал панелей читалки.

## Результаты

| Показатель | До | После |
|---|---:|---:|
| Холодный старт библиотеки, TTID median | 262.88 мс | 276.69 мс |
| EPUB, CPU frame P95 | 15.14 мс | 11.92 мс |
| EPUB, frameOverrun P95 | 4.39 мс | 4.63 мс |
| Нативный TXT, CPU frame P95 | — | 15.33 мс |
| Нативный TXT, frameOverrun P95 | — | 5.79 мс |

В этих выборках старт вырос на 5.3%, CPU P95 EPUB снизился примерно на 21%, overrun P95 изменился на +0.24 мс. Это не обещание отсутствия любых регрессий: пять стартов на одном телефоне не доказывают статистическую эквивалентность. Для нативного TXT исходной сопоставимой реализации не было; напрямую сравнивать его с другим EPUB-корпусом некорректно.

Начальный бюджет нативного CPU P95 — 16.7 мс. Частота 120 FPS для всех сценариев не объявляется достигнутой; положительный overrun на хвостах остаётся направлением дальнейшей оптимизации.

## Что сделано для ограничения нагрузки

- Парсеры работают вне UI-потока, native TextMeasurer — на последовательном worker.
- Кеш ограничен числом и весом; только одна страница предзагрузки.
- Смена темы не инвалидирует геометрию native-страниц.
- Скрытая библиотека отписывается от Room; сохранения позиции объединяются.
- Панели вне viewport текста используют фон бумаги, а не копируют весь WebView/Canvas ради размытия пустого поля.

## Этап сносок, цитат и подмены букв — 25 октября

Сравнение с предыдущим рабочим ReaderCore (`pixel-20261025.json`), а не с экспериментально медленным вариантом. Исходники текущего приложения: `ad00934`. Команда `ANDROID_SERIAL=47101FDAS0028Q ./gradlew :benchmark:connectedBenchmarkAndroidTest` завершилась `BUILD SUCCESSFUL in 3m 5s`, exit 0: три сценария без ошибок и пропусков. Те же 5 стартов и 3 × 12 перелистываний, CompilationMode.None.

| Показатель | ReaderCore MVP | Чтение + text morph |
|---|---:|---:|
| Библиотека, TTID median | 276.69 мс | 289.21 мс |
| EPUB, CPU frame P95 | 11.92 мс | 12.88 мс |
| EPUB, frameOverrun P95 | 4.63 мс | 0.34 мс |
| Native TXT, CPU frame P95 | 15.33 мс | 12.27 мс |
| Native TXT, frameOverrun P95 | 5.79 мс | 2.53 мс |

Старт в этой выборке вырос примерно на 4.5%, CPU P95 EPUB — на 8.1%; обе величины внутри заранее заданного допуска +15%. Native CPU P95 снизился примерно на 20%; хвосты overrun в обоих сценариях стали меньше. Это измерения одного Pixel, не универсальное обещание отсутствия любых просадок и не доказательство 120 FPS.

Первый вариант EPUB с отдельными DOM/WAAPI-элементами букв дал CPU P95 106.75 мс и был отброшен. Текущий вариант использует один Canvas-overlay и растры viewport; никаких сотен анимируемых DOM-слоёв. На Pixel подготовка координат и растра отдельно наблюдалась около 8–12 мс один раз на страницу, не на каждый кадр.

В подготовке замеров оглавление активируется accessibility-действием целевого приложения: входящие heads-up уведомления раньше перехватывали физический тап. Измеряемые перелистывания по-прежнему выполняются обычными касаниями. Уведомления и другие настройки телефона не изменялись.

```bash

```

Все шесть порогов — PASS, exit 0. Добавлены относительные проверки native CPU/overrun к предыдущей версии; абсолютный native бюджет 16.7 мс сохранён. Короткий диагностический запуск допускает `-Pandroid.testInstrumentationRunnerArguments.pageIterations=1`; итоговые числа выше взяты только из полного запуска с тремя повторами.

Исходники: `754f526` и `71540c1`. Полный повтор: `ANDROID_SERIAL=47101FDAS0028Q ./gradlew :benchmark:connectedBenchmarkAndroidTest` → `BUILD SUCCESSFUL in 3m 37s`, exit 0, три сценария. Та же методика: 5 холодных стартов и 3 × 12 перелистываний.

Первый полный замер новых настроек (`pixel-20261025-comfort-initial.json`, `754f526`) дал EPUB CPU P95 15.03 мс при лимите 14.81 мс: один из шести порогов был нарушен. Его результат сохранён, а допуски не менялись. В общем `GlassMaterial` добавлен fast path для однотонной бумаги: цвет тонировки вычисляется заранее, контур и тень остаются, бессмысленные на равномерном фоне blur/линза не запускаются. Полноценная оптика библиотеки сохранена.

Итоговый файл — `pixel-20261025-comfort.json`. Все шесть порогов относительно предыдущего рабочего чтения прошли:

```bash
python3 tools/check_performance.py benchmark/results/pixel-20261025-reading.json benchmark/results/pixel-20261025-comfort.json
```

Exit 0. CPU P95 EPUB вырос примерно на 5.8% и остаётся в допуске +15%; native CPU P95 снизился примерно на 13.1%. Native overrun P95 вырос до 4.42 мс и остаётся внутри допуска +2 мс к базе 2.53 мс; хвосты кадров ещё требуют работы. Это замер одного Pixel на стандартных настройках, не доказательство 120 FPS во всех книгах и комбинациях оформления.

## Разворачивание страницы и защита камеры

Код `fac0118` + `a6f7409`. Команда `ANDROID_SERIAL=47101FDAS0028Q ./gradlew :benchmark:connectedBenchmarkAndroidTest` завершилась `BUILD SUCCESSFUL in 5m 1s`, exit 0: 5/5 функциональных сценариев замера. Сохранены 5 холодных стартов и 3 × 12 перелистываний; добавлены native/EPUB focus-переходы, каждый 2 × 4 цикла открыть/закрыть (16 переходов на формат). CompilationMode.None, тот же Pixel. Результат: `pixel-20261025-focus.json`.

| Показатель | До перехода viewport | После |
|---|---:|---:|
| Библиотека, TTID median | 272.89 мс | 242.33 мс |
| EPUB, CPU frame P95 | 13.62 мс | 15.54 мс |

Native, разворачивание/сворачивание: CPU P95 **9.57 мс**, overrun P95 -3.74 мс.

EPUB, разворачивание/сворачивание: CPU P95 **15.96 мс**, overrun P95 6.79 мс.

Разворачивание обоих движков укладывается в начальный CPU-бюджет 16.7 мс. Вёрстка нативной страницы использует только два конечных размера; на каждом кадре двигается положение и маска, а не запускается пагинация. Команда перелистывания ждёт конечной геометрии.

```bash
python3 tools/check_performance.py benchmark/results/pixel-20261025-comfort.json benchmark/results/pixel-20261025-focus.json
```

**Exit 1: 7 PASS, 1 FAIL.** EPUB page-turn overrun P95 3.35 мс превышает лимит 2.35 мс (база 0.35 + допуск 2 мс). CPU P95 EPUB вырос примерно на 14.1% и остаётся внутри +15%; прочие шесть проверок также проходят. Пороги не изменены. Этот прогон не объявляется полностью свободным от регрессий или доказательством 120 FPS. Он включает два новых focus-сценария и отличается от прежнего трёхсценарного прогона порядком и нагрузкой на телефон; одного сравнения недостаточно для установления причины хвоста EPUB.

Первый запуск новых focus-сценариев проверял исчезновение панели до завершения её fade; добавлено явное ожидание и координаты внутри окна приложения. Во втором запуске native focus прошёл, а EPUB setup встретил пустой ответ Android 17 am-start completion. Подготовка теперь подтверждает фактическую библиотеку целевого приложения при таком ответе; измеренный cold-start сценарий не менялся. Финальный полный прогон всех пяти сценариев прошёл. Промежуточные данные сохранены в локальном аудите `app/build/reports/focus-stage/`; они не подменяют финальные числа выше.
