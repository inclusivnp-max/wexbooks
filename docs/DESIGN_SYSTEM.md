# WexBooks — Liquid Glass / iOS-inspired

Дата решения: 25 октября 2026. Статус: Backdrop подключён и используется в интерфейсе.

## 1. Выбор библиотеки

| Вариант | Что даёт | Решение для WexBooks |
|---|---|---|
| **Kyant Backdrop / AndroidLiquidGlass 2.0.1** | Захват реального Compose-фона, blur, преломление линзой, подсветка краёв; собственные компоненты поверх общего движка | **Выбран.** Точно соответствует направлению Liquid Glass и оставляет полный контроль над книжным интерфейсом |
| **Haze 2.0.1** | Модульная система Blur и Glass; подробная документация эффектов и настроек | Сильная альтернатива. Glass в этой выпущенной версии ещё experimental; второй движок параллельно не добавляем |
| **Liquify** | Развивает идеи Backdrop, включая объединяющиеся жидкие поверхности | Кандидат для отдельного эксперимента позже, не основание первой версии |
| **PrismalAGSL** | Compose-компоненты, эффекты преломления и несколько аппаратных путей отрисовки | Проверять отдельно при потребности в его компонентах; сейчас одного Backdrop достаточно |

Это выбор под продукт, а не утверждение об абсолютном превосходстве по скорости. Сравнительный GPU-бенчмарк библиотек ещё не проводился.

## 2. Подключение

Maven Central: `io.github.kyant0:backdrop:2.0.1`, версия закреплена в version catalog. JitPack и плавающие версии не используются.

Для совместимости с опубликованной Kotlin metadata Backdrop стек выровнен: Kotlin/Compose compiler 2.4.20 и AndroidX Compose BOM 2026.09.00. AGP 9.3.3 и Gradle 9.5.0 сохранены. KGP обновлён через buildscript, как предусмотрено AGP с built-in Kotlin.

Общая точка подключения — `Modifier.wexGlass()` в `app/src/main/java/client/wexbooks/ui/glass/GlassMaterial.kt`.

```kotlin
val backdrop = rememberLayerBackdrop()
Box {
    BookOrLibraryContent(Modifier.layerBackdrop(backdrop))
    Controls(Modifier.wexGlass(backdrop, darkTheme, reduceTransparency))
}
```

Содержимое и стекло — соседи. Стеклянную панель не включаем в фон, который она захватывает. Иначе возникает обратная связь отрисовки.

### Профили материала
- Android 9–11 / API 28–30: плотная поверхность с контуром.
- Android 12 / API 31–32: захват фона и blur, без RuntimeShader-линзы.
- Android 13+ / API 33+: blur и линза с преломлением.
- «Меньше прозрачности»: плотная поверхность на любой версии, эффекты не запускаются.

Проверки выбора профиля — unit-тесты. Реальная визуальная проверка каждого поддерживаемого API входит в релизную матрицу.

## 3. Визуальный язык

**Ощущение:** дорогая спокойная читалка, а не коллекция эффектов.

- Большие уверенные заголовки; редакционная serif-типографика на обложках и в тексте.
- Тёплая светлая бумага, чернильный текст, глубокая спокойная тёмная тема.
- Цвет обложки — акцент, а не фон каждой страницы.
- Капсульная плавающая навигация, отдельные круглые действия, мягкие края и узкие блики.
- Свои тонкие иконки; ясные подписи под основной навигацией.
- Отступы кратны 4; основная сетка — 8; горизонтальные поля телефона — 20–28 dp.
- Скругления основных карточек — около 28–32 dp, небольших контролов — 20–24 dp.
- Цвет текста и контраст проверяются и поверх светлого, и поверх пёстрого фона.
- На странице книги нет градиентных бликов, blur текста или постоянного движения.

iOS — ориентир по материалам, иерархии и тактильному ощущению. Навигация Android, системный Back, масштабирование текста и доступность сохраняются.

## 4. Где используем стекло

| Элемент | Материал |
|---|---|
| Нижняя навигация библиотеки | Одна общая стеклянная капсула, спокойное выделение активного пункта |
| Кнопки назад / тема | Компактные стеклянные круги, пружинное нажатие |
| Панель инструментов чтения | Стекло только при открытой панели; основной текст остаётся на своей бумаге |
| Настройки шрифта и оглавление | Короткие панели с достаточной плотностью фона; качество после измерений |
| Длинные списки книг, текст книги, заметки | Обычные стабильные поверхности, без отдельного blur на каждой строке |

В библиотеке стекло использует живой фон. В EPUB и нативной читалке панели расположены вне текстового viewport: их источником служит бумага страницы, без дорогостоящего захвата всего текста/WebView.

## 5. Движение и управление

Отдельная спецификация: [Motion system](MOTION.md).

- Нажатия реагируют сразу; небольшое пружинное сжатие подтверждает действие.
- Анимация не задерживает открытие контента. Переходы короткие и прерываемые.
- При переключении вкладок сохраняем выбранную вкладку, а при пересоздании Activity — основные настройки прототипа.
- Реальная читалка сохраняет позицию через отдельное хранилище, не через Compose-состояние экрана.
- В продуктовой версии добавляем «меньше движения», отключаем лишнюю тактильную отдачу по выбору пользователя.
- Ключевые действия доступны без скрытых жестов; рабочая зона около большого пальца.

## 6. Производительность и доступность

Цели, а не результаты измерения текущего прототипа:
- Тяжёлые эффекты ограничены небольшими видимыми панелями; один общий захват фона.
- Предпочитаем самый простой материал, который сохраняет нужное ощущение.
- Проверяем release/profileable-сборку на 60/90/120 Гц, слабом устройстве и после прогрева.
- Не анимируем оптику бесконечно, когда экран неподвижен.
- Для будущего WebView/Readium проверяем реальный захват пикселей отдельно: Compose-фон прототипа не доказывает совместимость с книжным renderer.
- Тестируем TalkBack, системный крупный шрифт, альбомную ориентацию, светлую и тёмную тему, большие сенсорные зоны.
- Непрозрачное оформление — полноценный пользовательский режим, не временная заглушка.

## Исправление цветов

- Общая тема задаёт LocalContentColor из onBackground: элементы вне Surface не наследуют случайный чёрный цвет.
- Панели читалки используют ReaderIconAction с явными обычным, выбранным и отключённым цветами.
- Цвета EPUB передаются до первого показа страницы, а не только после появления контроллера.
- Вторичный текст светлой темы: #636B75 на #F7F6F2, расчётный контраст 4.99:1.
- Пиксельные тесты на Pixel проверяют текст и иконки обеих тем; библиотека, читалка и панели проверяются отдельно.
