# WexBooks — правила работы

## История изменений
- Использовать Git: небольшие осмысленные коммиты и просмотр diff перед коммитом.
- Не создавать копии проекта, папки backup/original/modified или архивы перед каждым изменением. История исходников уже хранится в Git.
- Не перезаписывать пользовательские незакоммиченные изменения. Откат делать точечно через Git.
- keystore/, keystore.properties, local.properties, .idea/, .gradle/, .kotlin/ и результаты сборки оставлять вне Git. Пароли подписи не выводить.

## Продукт и интерфейс
- Продуктовый план: docs/PRODUCT_PLAN.md. Дизайн-система: docs/DESIGN_SYSTEM.md.
- Интерфейс — Jetpack Compose; направление — iOS-inspired Liquid Glass с собственной идентичностью WexBooks.
- Единственный подключённый движок стекла — Kyant Backdrop. Общие эффекты держать в ui/glass/GlassMaterial.kt, не размножать настройки по экранам.
- Стекло предназначено для элементов управления, не для книжного текста. Захватываемый фон и стеклянные элементы должны быть соседями, без циклического захвата.
- Сохранять minSdk 28: непрозрачный материал до API 31, blur на API 31–32, линза на API 33+. Уважать настройку уменьшения прозрачности.
- Явно отличать визуальный прототип, демо-текст и работающие функции чтения пользовательских книг.

## Проверки
- После изменений кода запускать подходящие unit-тесты и сборку; интерфейс проверять на пользовательском Pixel 9 Pro XL через USB ADB, серийный номер 47101FDAS0028Q. Эмуляторы не запускать.
- Для connectedDebugAndroidTest явно задавать ANDROID_SERIAL=47101FDAS0028Q. Debug использует отдельный applicationId client.wexbooks.dev; основную установленную сборку и её данные сохранять. Не запускать одни тесты повторно через Wi-Fi-подключение того же телефона.
- Перед коммитом проверять git diff --check и отсутствие ключей/паролей среди отслеживаемых файлов.
